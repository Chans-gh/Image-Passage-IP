# 内容结构：主题、价值、模板、篇幅、钩子

本文件定义「讲什么、为什么看、怎么讲、用几张图、用什么吸引点击」。视觉见 `visual-system.md`，文案见 `copywriting.md`。

决策顺序（每个变量只回答一个问题）：

```
D 主题领域（讲什么）
→ R 读者价值（为什么看）＋ I 互动目的（希望读者做什么）
→ F 篇幅形态（用几张图）
→ T 内容模板（怎么讲）
→ H 钩子（封面和标题用什么吸引点击）
→ 视觉：V 风格 → C 封面形态 → L 版式 → E 表达元素（visual-system.md）
→ 文案：标题、正文（W 写法、S 字数档、K 口吻）、标签、合规（copywriting.md）
```

主题回答「讲什么」，模板回答「怎么讲」。主题不和性别、模板或画风绑定。

### 互动边界（所有 I 通用，不可覆盖）

- **不捏造**：不编造评论、读者反馈、「评论区精选」；回复真实评论时用用户提供的原文。
- **不诱导**：不写「点赞过百更新」「评论扣 1 领取」「关注后私信领资料」等换取互动的口令；不做站外导流。
- **不引战**：投票和讨论不设性别、地域、群体对立的选项。
- **不强加**：I00 是合法选项，不强制每篇都有互动句。

## 三、内容模板 T

按**读者最主要的收获**选一个主模板，不按话题或页面外形选。必要时借用一个辅助模板提供局部结构，但只用主模板决定写法和字数档。箭头表示叙事环节，**不表示一环占一页**。模板是选择工具，不是强制填空。

### T01｜教程／工作流
适合：工具操作、从零开始、技能入门、流程搭建。
结构：要完成的任务 → 适用条件／准备 → 核心步骤 → 实际示例 → 易错点 → 完整流程与第一步。
必须：输入、动作、输出清楚；必要时展示可检查的结果。
避免：只列功能，缺少完成任务的路径。

### T02｜案例／方法
适合：案例拆解、多种做法、经验方法。
结构：问题 → 判断标准 → 案例／方法 → 横向归纳 → 如何开始。
必须：每个案例说明场景、做法和可借鉴条件；数量服务于判断。
避免：案例来源不明，或每个方法只是名称不同。

### T03｜趋势／资讯／行业判断
适合：产品变化、模型发布、公司动作、市场、政策与行业观察。
结构：关键变化 → 为什么关注 → 已确认事实 → 背景与影响 → 分析判断 → 行动建议与待观察变量。
必须：事实、判断和待观察分开；数据、时间和功能状态有来源。
避免：把媒体猜测、宣传话术或推演写成确定事实。

### T04｜对比／选型
适合：工具、物品、服务、方案和路线选择。
结构：明确需求 → 比较标准 → 核心差异 → 场景匹配 → 不适合的条件 → 选择建议。
必须：比较对象与条件可比；把差异翻译成对读者的实际影响。
避免：只列参数，或无依据地宣布「最好」。

### T05｜层级／自测／互动
适合：技能阶段、自查、状态识别和轻互动。
结构：自查问题 → 判断坐标 → 不同表现 → 如何改进 → 下一步行动／讨论。
必须：用可观察行为区分类型；自编模型标注为「本篇整理的框架」。
避免：人格贴标签，或把趣味自测包装成诊断。

### T06｜清单／资源整理
适合：物品准备、资源目录、工具包、收藏清单。
结构：使用场景 → 筛选标准 → 分组条目 → 适用条件与使用顺序 → 优先从哪项开始。
必须：每个条目说明为什么入选、何时使用；链接、价格和可用性要核实。
避免：无标准堆数量、复制营销清单。

### T07｜避坑／纠错
适合：常见误区、失败排查、错误示范与改进。
结构：具体做法 → 可能的问题 → 原因与条件 → 修正动作 → 对照示例 → 自查要点。
必须：说明错误成立的条件，给出可执行的修正。
避免：把个人偏好说成普遍禁忌。

### T08｜体验／测评
适合：工具、生活用品、服务与实际使用观察。
结构：想验证的问题 → 样品／版本／测试条件 → 观察记录 → 优点与限制 → 适合谁 → 结论。
必须：说明测试主体、观察时间、条件和局限。使用者亲测需要其提供依据；助手实际执行的可验证测试要说明测试主体；引用公开测试要标注原测试者，不能改称使用者亲测。没有实测时，在策划阶段推荐「资料对比」或「测评方案」；已确认的实测任务不能静默换成另一种内容。
避免：虚构使用经历、数据或前后效果。

### T09｜经历／故事复盘
适合：转岗、学习、项目、生活变化与阶段总结。
结构：起点 → 关键选择 → 行动与转折 → 结果 → 反思 → 可借鉴条件。
必须：真实经历有素材；虚构或复合案例明确标注；个人结果说明条件。
避免：给使用者编造第一人称经历，把个案包装成必然路径。

### T10｜共鸣／观点
适合：工作与生活处境、成长观察、关系边界。
结构：具体处境 → 感受与问题 → 原因或另一种解释 → 新视角 → 一个小行动／开放结尾。
必须：有场景、有理由，容纳不同处境。
避免：空泛金句、制造性别对立、替读者下心理诊断。

### T11｜沟通／话术
适合：提出需求、拒绝、反馈、协商和澄清。
结构：人物与场景 → 沟通目标 → 常见表达与改写 → 表达逻辑 → 使用边界与替代说法。
必须：说明角色关系和权力差异；话术作为可调整的示例。
避免：承诺一句话解决复杂关系，或伪造真实聊天截图。

### T12｜挑战／习惯养成
适合：阅读、练习、整理、学习和长期行动。
结构：目标与起点 → 最小行动 → 阶段计划 → 记录工具 → 遇阻调整 → 阶段复盘。
必须：目标可观察、行动可持续，允许调整；计划与已完成的记录明确区分。
避免：把预设计划写成已实现的成果。

### T13｜攻略／安排
适合：出行、路线、活动、准备事项和日程安排。
结构：人群与约束 → 推荐安排 → 时间／预算／空间顺序 → 关键提醒 → 备选方案 → 出发或执行清单。
必须：营业、交通、预约、收费等会变化的信息要核实，并注明适用日期。
避免：无视预算、移动时间、体力与个人限制。

### T14｜概念／原理科普
适合：生活知识、AI 概念、文化常识、兴趣入门。
结构：一个问题 → 基本概念 → 机制／分类 → 生活例子 → 常见误解 → 如何应用或继续了解。
必须：区分定义、类比与例外；图鉴、分类表和 FAQ 可作为子结构。
避免：用类比替代事实，或把简化模型说成完整原理。

### T15｜审美／作品拆解
适合：穿搭、家居、摄影、设计、艺术和作品分析。
结构：目标效果 → 关键元素 → 组合关系 → 对照分析 → 可借鉴动作 → 适用场景。
必须：区分可观察特征与个人偏好，标明引用作品与素材的来源。
避免：只说「高级」「有氛围」，不给具体观察和操作。

### T16｜分享／记录
适合：plog、OOTD、日常记录、晒图、旅行片段、作品展示。
结构：一个瞬间或主题 → 画面 → 细节 → 一句感受 → 可选的实用信息（地点、单品、参数）。
必须：画面使用用户提供的真实照片；生成的图只能作为版式装饰或明确标注为插画。
避免：AI 生成图冒充实拍；硬加「干货」变成别的模板。

### T17｜单品推荐／种草
适合：一个物品、一款工具、一家店、一本书。
结构：适合谁、什么场景 → 推荐理由（1～3 条）→ 怎么用 → 不适合谁或有什么限制 → 价格和渠道（注明日期）。
必须：说明推荐依据（亲测需要用户提供依据）；有商业合作时必须标注；写出限制。
避免：只有优点；绝对化用语；功效承诺。

### T18｜征集／提问／求助
适合：求推荐、求建议、征集经验、征集作品、请大家补充。
结构：我的处境和条件 → 一个具体的问题 → 已经尝试或考虑的选项 → 希望得到什么样的回答。
必须：问题具体、可回答；交代足够的条件。
避免：捏造评论或「评论区精选」；问题空泛到无法回答。

### T19｜投票／选择题
适合：二选一、多选一、站队讨论、你会怎么做。
结构：情境 → 选项 A/B（最多 4 个）→ 每个选项的代价或特点 → 邀请选择（作者倾向可选）。
必须：选项可比、条件对等；可以讨论但不引战。
避免：性别、地域、群体对立；用投票包装已有结论。

### T20｜可用物料／模板图
适合：手机壁纸、打卡表、计划表、速查卡、手账模板、清单模板。
结构：物料本体（图）→ 使用说明（正文）→ 适配说明（尺寸、打印、使用场景）。
必须：素材和字体有使用授权；物料本身可直接使用，不是宣传图。
避免：用「评论区扣 1 领取」之类的方式换取互动。

### T21｜通知／预告／招募
适合：账号公告、连载预告、更新说明、活动招募、直播预告。
结构：一句话说明是什么 → 时间、地点、方式、规则 → 参与方式或注意事项。
必须：时间、规则、条件准确完整；涉及抽奖或福利时遵守平台规则。
避免：诱导关注、点赞、转发；夸大福利。

### T22｜趣味／吐槽
适合：职场梗、生活小尴尬、反差对比、自嘲。
结构：熟悉的情境 → 反差或夸张 → 落点（笑点或一句共鸣）。
必须：素材自有或可合法使用；明确是夸张表达。
避免：攻击特定群体或个人；直接使用影视截图、表情包等有版权的素材。

### T23｜访谈／他人故事
适合：人物访谈、朋友的经历、读者投稿、从业者分享。
结构：人物与背景 → 关键经历 → 做法或观点 → 作者的观察 → 可借鉴条件。
必须：内容来自真实的访谈或投稿，并取得当事人同意；隐去不必要的个人信息；作者观点和当事人原话分开。
避免：虚构人物冒充真实访谈；把当事人的个案写成普遍规律。

### 压缩规则（适用于所有 T）

- 模板的叙事环节不等于页数。F1、F2 只保留「核心观点＋最关键的支撑」，其余环节移到正文。
- 模板「必须」项中影响判断的条件（来源、测试条件、适用人群）不能因为压缩而丢失。放不进图片时写进正文，并在图上留一句简短提示。
- 默认篇幅由信息量决定，不凑页，也不硬压。用户指定张数时照做。
- 3 页内容可合并「背景与标准」「结果与行动」，但不能丢失理解所需的条件。

## 五、钩子 H（封面和标题共用）

| 编号 | 钩子 | 示例方向 | 真实性要求 |
|---|---|---|---|
| H01 | 结果展示 | 做完是这样的 | 结果真实，或标注为示意 |
| H02 | 痛点问题 | 是不是总遇到…… | |
| H03 | 场景代入 | 周一早上 9 点的会议室 | |
| H04 | 核心主张／反常识 | 其实不用…… | 有理由支撑，不为反常识而反常识 |
| H05 | 数字清单 | N 个 / N 步 / N 分钟 | 数字和内容对应 |
| H06 | 对比反差 | 前后、A 与 B | 对比条件一致 |
| H07 | 人群定位 | 新手、租房的人、第一次带娃 | 不用性别化称呼作为默认 |
| H08 | 悬念提问 | 为什么……？ | 正文要回答 |
| H09 | 资源价值 | 合集、模板、可直接保存 | 资源真实可用 |
| H10 | 时效新闻 | 刚发布、今年起 | 核实并注明日期 |
| H11 | 故事起点 | 那天我…… | 需要真实经历 |
| H12 | 情绪金句 | 一句戳心的话 | 不贩卖焦虑 |
| H13 | 选择投票 | 你选哪个？ | 选项对等 |
| H14 | 数据权威 | 有来源的关键数字 | 必须有来源 |
| H15 | 身份背书 | 做了 5 年 HR 告诉你 | 必须真实（profile B 组） |

规则：

- 封面和标题用同一个钩子，或互补的两个钩子（例如封面 H06 对比、标题 H07 人群），不逐字重复。
- 钩子强度与证据强度匹配：H10、H14 要有来源；H11、H15 要有真实依据。
- 封面怎么摆见 `visual-system.md` 的封面形态 C；封面主文案的字数见 `visual-system.md` 第四节。

## 六、页面角色

页序角色不固定，按体裁安排：

| 角色 | 作用 | 常见做法 |
|---|---|---|
| 封面 P1 | 让目标读者知道主题和阅读价值 | 用钩子 H；结果、问题、场景、主张、数字…… |
| 起始内页 | 进入主题 | 可以先给结论、冲突、条件、标准、路线或概念，不强制先解释「为什么」 |
| 中间页 | 真正的信息推进 | 每页一个核心观点；相邻页不换词重复 |
| 目录页 | F5 长套的导航 | L34，和正式页码对应 |
| 收束页 | 按体裁收束 | 总结、选型表、行动、复盘、清单或余味；不必每篇都画完整流程，不复述全部内容 |

每页最低结构：页面级主标题、一个核心观点、必要短文案、一个主版式、清晰的信息焦点。焦点已由标题或画面表达时，不再加重复的结论卡片。
