# 发布文案：标题、正文、标签、首条评论、合规

本文件是文案数值默认、字数口径、写法、口吻、标签、首条评论和合规的唯一定义来源。平台上限在 `platforms/*.md`；钩子 H 在 `content-templates.md` 第五节；封面主文案在 `visual-system.md` 第四节。

## 一、原则

1. **两类约束分开**：
   - **平台上限**是外部硬约束，不能被配置覆盖。用户要求超过上限时，说明无法发布并给出拆分方案。
   - **项目默认**在平台上限之内，按「当次 ＞ 本次已确认 ＞ 账号长期（profile）＞ 项目默认」继承，可以被覆盖。
2. **由变量驱动**：写法由 T 决定；图文分工由 F 决定；收尾和互动由 R、I 决定；标题用 H；语气用 K。
3. **真实性不可覆盖**：第一人称、亲测、背书、数据必须有依据。
4. **文案不等图**：只要文案的任务可以直接执行，不等待图片。

## 二、文案的组成

| 组成 | 位置 | 定义 |
|---|---|---|
| 封面主文案 | 图上 | `visual-system.md` 第四节 |
| 发布标题 | 发布栏 | 第三节 |
| 正文 | 发布栏 | 第四～七节 |
| 话题标签 | 正文末尾 | 第八节 |
| 来源与日期 | 正文，或图上的来源条 E09 | 第十节 |
| 互动句 | 正文末尾 | 由 I 决定（`content-templates.md` 第二节） |
| 合规标注 | 正文开头或末尾 | 第九节 |
| 首条评论 | 评论区，发布后由账号自己发出 | 第十四节 |

## 三、发布标题

- 项目默认 ≤20 字（编辑默认，不是平台规则）。
- 写清具体问题、收获、场景或判断，让读者一眼知道和自己有没有关系。
- 和封面主文案用同一个钩子或互补钩子，不逐字照抄。
- 钩子强度与证据强度匹配：H10、H14 要有来源；H11、H15 要有真实依据。
- 不夸大效果，不把个案写成普遍结果，不制造焦虑、性别对立或群体对立。
- 没有用户提供的依据，不写「亲测」「我坚持了」「我靠它获得」。
- 商业内容不用绝对化用语（第九节）。
- 不要求套固定句式。

## 四、图文分工（由 F 决定）

| 篇幅 | 图片承担 | 正文承担 | 字数档调整 |
|---|---|---|---|
| F1 单图 · 信息型（一图看懂、清单、物料） | 全部核心信息 | 简短说明用法和条件 | 降一档 |
| F1 单图 · 钩子型（大字报、提问、投票） | 一个观点或问题 | 背景、理由、展开 | 升一档 |
| F2 双图 | 钩子＋交付 | 补充条件和细节 | 不变 |
| F3～F5 套图 | 主体内容 | 补充图片没展开的条件、经验、细节和延伸 | 不变 |

正文不是逐页转写图片，也不能提出与图片证据矛盾的新结论。

## 五、正文字数档 S

| 档 | 字数 | 默认适用的主模板 |
|---|---|---|
| S0 一句话 | ≤50 字 | T16、T22 的 F1 |
| S1 短 | 50～150 字 | T16、T19、T20、T21、T22 |
| S2 中短 | 150～300 字 | T10、T11、T17、T18 |
| S3 中 | 300～500 字 | T01、T02、T04、T05、T06、T07、T08、T12、T13、T14、T15 |
| S4 长 | 500～800 字 | T03、T09、T23 |
| 上限 | 平台上限 | 不能超过（`platforms/*.md`） |

- 先按**主模板**取默认档，再按第四节升降**一档**。
- 混合模板只按主模板取档，不累加；不按某一页的版式判断。
- 信息已经完整时不为凑字数重复；没有硬性字数要求时，可以为完整表达小幅偏离，并简要说明。用户明确了字数时照做。

### 字数口径

- 标题和正文分别统计。
- 按可见字符计：汉字、字母、数字、标点各计 1；不计空格和换行；一个 emoji（含肤色、组合）计 1。
- 话题标签、完整链接、交付说明另计，不计入正文。
- 这是内部一致性口径，不冒称平台的计数方式。
- 统计：`python3 scripts/check_copy.py --count "文字"`

## 六、正文写法 W

| 编号 | 写法 | 骨架 | 对应模板 |
|---|---|---|---|
| W1 | 方法型 | 补一个图里没展开的关键条件 → 第一步怎么做 → 常见卡点 → 进阶建议 | T01、T02、T07、T14、T15 |
| W2 | 判断型 | 为什么值得关注 → 事实与推演分开 → 对读者的影响 → 后续观察点 | T03 |
| W3 | 选择型 | 筛选依据 → 预算、时间、人群条件 → 替代方案 → 信息更新条件 | T04、T06、T13、T17 |
| W4 | 体验型 | 背景与条件 → 关键观察 → 局限 → 适合谁 | T08 |
| W5 | 叙事型 | 起点 → 关键选择 → 结果 → 反思 → 可借鉴条件 | T09、T12、T23 |
| W6 | 情感型 | 具体处境 → 有理由的新视角 → 边界或替代说法 → 小行动或余味 | T10、T11 |
| W7 | 互动型 | 情境 → 明确的问题或选项 → 作者已知的信息 → 希望怎样回答 | T05、T18、T19 |
| W8 | 记录型 | 一个瞬间 → 细节 → 一句感受 → 可选的实用信息 | T16、T22 |
| W9 | 说明型 | 是什么 → 怎么用，或时间、地点、规则 → 注意事项 | T20、T21 |

骨架是参考，不要求每篇填满所有环节。段落短而连贯，避免排比和连续金句。

## 七、口吻 K

### 维度

| 维度 | 取值 |
|---|---|
| 距离 | 专业 ↔ 朋友 |
| 温度 | 克制 ↔ 热情 |
| 节奏 | 精炼 ↔ 絮语 |
| 人称 | 无人称 / 我 / 我们 / 你 |
| emoji 密度 | 无 / 少（全文 1～3 个）/ 适中（4～8 个） |
| 称呼 | 默认用「你」或不称呼；不默认使用「姐妹们」等性别化称呼 |

### 预设

| 编号 | 预设 | 距离 | 温度 | 节奏 | 人称 | emoji | 适合 |
|---|---|---|---|---|---|---|---|
| K1 | 专业顾问 | 专业 | 克制 | 精炼 | 无人称 / 我们 | 无～少 | T03、T04、⛔ 领域 |
| K2 | 耐心讲解 | 中间 | 中间 | 精炼 | 你 | 少 | T01、T14 |
| K3 | 靠谱朋友 | 朋友 | 中间 | 中间 | 我 / 你 | 少～适中 | T06、T07、T13、T17 |
| K4 | 轻松吐槽 | 朋友 | 热情 | 短句 | 我 | 适中 | T22、T19 |
| K5 | 克制记录 | 中间 | 克制 | 精炼 | 我 | 无 | T09、T08、T23 |
| K6 | 个人日记 | 朋友 | 中间 | 絮语 | 我 | 少～适中 | T16、T10 |

- profile 里选一个默认预设，可以单篇覆盖；单篇内保持一致。
- profile 的称呼、常用表达、禁用词、emoji 习惯叠加在预设之上。

### 第一人称与真实经历

- 第一人称「我」只用于有真实依据的经历，主体要一致。
- 引用他人测试不能写成「我用下来」；助手执行的测试标注执行者；没有用户经历依据时用通用说明或明确的示例。
- 建议、个人偏好、事实和引用分清，不把个人感受包装成统计结论。
- 真实人物、经历和聊天内容只用本次提供且适合公开的必要信息。
- 观点类允许情感表达，但不替读者定义人格、关系或心理状态。

## 八、话题标签

- 默认 3～6 个，最多 8 个（平台上限，`platforms/*.md`）。
- 组成：1～2 个核心主题词＋1～2 个场景或人群词＋0～1 个系列标签；profile 有固定标签时放在前面。
- 只用和内容相关的标签，不蹭无关热点。
- 格式：`#标签`，空格分隔，放在正文末尾。不计入正文字数。

## 九、合规

| 场景 | 要求 |
|---|---|
| 商业合作 | 按平台要求标注合作关系；不把广告写成「自发分享」 |
| 绝对化用语 | 商业或推荐内容不用「最、第一、唯一、顶级、100%」等 |
| 功效宣称（D07、D09 涉及健康、D10） | 不承诺功效，不说「治疗」「根治」；写明条件和个体差异 |
| 投资与收益（D17） | 不给个体化投资建议，不承诺收益；注明「不构成投资建议」 |
| 医疗、心理、法律（D10、D14、D20） | 不诊断、不开方、不替代专业意见；关键结论用专业来源；加提示语 |
| 诱导互动 | 不写换取点赞、收藏、关注、评论的口令；不做站外导流 |
| 未成年人与他人隐私 | 不露出儿童正脸、学校、住址等；他人信息需要同意 |

具体条款以平台最新规则为准。`check_copy.py` 只做词表级别的提醒，不能代替判断。

## 十、来源与更新

- 有关键事实、数据、引文、作品或变化信息时，在正文或图上来源条给出可识别的来源和日期。
- 图上放简短来源；完整链接放正文、首条评论或交付说明，不用二维码或长链接挤占主要信息。
- 价格、营业、版本、预约等按适用日期表达。
- 引用原话准确并保持必要长度；自己的归纳不用引号冒充原话。
- 专业主题按专业来源、适用条件和已知边界表达；不用无依据的确定性承诺。

## 十一、互动

- 由 I 决定（`content-templates.md` 第二节）。只有内容自然需要时加一个互动邀请：分享实际差异、在明确条件下讨论选择、补充其他做法或资源、提出希望继续展开的问题。
- 不强制每篇都有互动句；不用无意义口令；不捏造评论或反馈。
- 互动问题放在正文末尾或首条评论，二选一，不重复。

## 十二、默认交付

完整套图出图后，默认交付四项，顺序固定：

1. **标题**：一个发布标题。
2. **正文**：一版符合主模板和字数档的完整正文，末尾附话题标签；需要时含来源与日期、合规标注、自然的互动句。
3. **图片**：`final/P01.png`～`final/PNN.png`，按发布顺序。
4. **首条评论**：一条（第十四节）。

用户说不要首条评论时省略。只要文案时交付标题、正文、首条评论，不含图片。

- 用户只要图、只要文案、要提前文案、多个版本或其他长度时，按有效范围执行，不额外等待或生成其他资产。
- 图片完成前的文案标为「文案版本」，不声称已与图片逐页核对；图片完成或改动后再同步最终文案。

## 十三、`copy.md` 与检查

`copy.md`（模板见 `templates/copy.md`）第一行的注释写明元信息，检查脚本会读取：

```markdown
<!-- 版本：v1 · 平台：xiaohongshu · 主模板：T01 · 字数档：S3 · 领域：D13 · 商业：否 -->
```

```bash
python3 scripts/check_copy.py <项目>/copy.md --profile image-passage-work/profile.md
python3 scripts/check_copy.py <项目>/copy.md --commercial   # 商业内容：绝对化用语记为错误
```

脚本检查：标题长度、正文字数档、标签数量、封面主文案长度、首条评论（是否填写、长度）、绝对化用语、功效和收益承诺、诱导互动口令、profile 禁用词、敏感领域提示语、商业合作标注。第一人称用词只作提示，由你核对依据。

## 十四、首条评论

发布后由账号自己发出的第一条评论，平台支持时置顶。它不是读者评论，也不是正文的复述。

### 写什么（按内容选一项为主，最多两项）

| 用途 | 适合 | 示例方向 |
|---|---|---|
| 补充信息 | 正文放不下的清单、参数、完整来源链接、适用日期 | 「文中提到的三本书：……」 |
| 条件与边界 | T03、T08、⚠️ / ⛔ 领域 | 「以上是室内散射光的情况，北方冬季暖气房要……」 |
| 讨论问题 | I03～I05 等需要读者评论的互动目的（`content-templates.md` 第二节） | 一个具体、可回答的问题，并给出作者已知的情况 |
| 更新与勘误 | 时效内容、系列内容 | 「10 月 30 日更新：……」 |
| 系列索引 | 系列内容 | 上一篇、下一篇的主题（不放站外链接） |

### 要求

- 项目默认 ≤150 字，统计口径同正文（第五节）；口吻与正文一致（第七节）。
- 不重复标题和正文已有的句子；不逐页复述图片。
- 互动问题如果放在首条评论，正文末尾就不再重复（第十一节）。
- 不写换取点赞、收藏、关注、评论的口令；不放联系方式、二维码、站外导流。
- 不冒充读者，不捏造他人评论或反馈；第一人称经历同样需要真实依据。
- 商业合作的标注必须在正文里，不能只放在首条评论。
- 事实、来源、合规规则与正文相同（第九、十节）。
