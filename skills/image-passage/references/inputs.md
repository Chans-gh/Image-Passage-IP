# 输入：形式、归一化与素材用途

## 一、原则

- **一句话就能开工**。素材越真实、越完整，成品上限越高，但不要求一次给齐。
- **形式不等于用途**。同一张图片可能要放进页面，也可能只是风格参考。先判断用途，再决定怎么用。
- **先归一化，再创作**。所有输入整理进 `<项目>/inputs.md`，原文件复制到 `<项目>/inputs/`。后续阶段只读这两处，不反复回看聊天记录。
- **能力不够时如实说明**。处理不了某种输入（例如纯文本模型看不了图片），说清楚缺什么、可以怎么补，不假装读过。

## 二、输入形式与处理

| # | 形式 | 处理方式 | 处理不了时 |
|---|---|---|---|
| 1 | 一句话 | 判断主题 D，推断读者和价值 | — |
| 2 | 一段话 / 口述稿 | 拆出事实、观点、经历和情绪 | — |
| 3 | 文档：md、txt、docx、pdf、pptx、html | `scripts/extract_input.py doc <文件> --out inputs/<名>.txt` | 请用户粘贴正文 |
| 4 | 表格：xlsx、csv、测试记录 | 同上；数据供表格、对比、图表类版式使用 | 请用户粘贴关键数据 |
| 5 | 实拍照片 | 看图描述内容；判断能否作为上图素材 | 不能看图：请用户每张写一句说明。图片仍可嵌入页面 |
| 6 | 截图 | 读出文字和数字；检查隐私信息 | 不能看图：用 OCR（`ocr_check.py` 需要的 tesseract）；没有 OCR 时请用户说明 |
| 7 | 手写 / 手绘稿 | 识别结构，转成策划草稿 | 请用户口述 |
| 8 | 参考图 | 只提取风格参数，不复制构图和内容 | 不能看图：请用户用文字描述风格 |
| 9 | 角色图 | 进入角色资产流程（`characters.md`） | 不能看图：请用户填写特征卡 |
| 10 | 网页 / 文章链接 | 抓取正文，记录来源和抓取日期 | 需要登录或被拦截：请用户粘贴正文或截图 |
| 11 | 小红书 / 微信笔记链接 | 通常需要登录，大多抓不到 | 请用户截图。他人笔记只作参考 |
| 12 | 视频链接 | 只能拿到标题和简介 | 请用户提供文字稿或视频文件 |
| 13 | 音频 | 转写成文字稿，再按第 2 项处理 | 见第三节 |
| 14 | 视频文件 | 抽音轨转写＋抽关键帧 | 见第三节 |
| 15 | 已有成稿：自己的长文、旧笔记 | 改写为图文：压缩、拆页、换结构 | — |
| 16 | 已有项目：「继续上次」「改第 3 页」 | 读 `state.json`，从未完成的节点继续 | — |

## 三、音频与视频

音频分三档：

1. 环境本身能理解音频：直接用。
2. `.env` 配置了 `TRANSCRIBE_API_*`：`python3 scripts/extract_input.py transcribe <音频> --out inputs/transcript.txt`
3. 都没有：请用户用手机或会议软件自带的转文字功能，粘贴文字稿。

视频 = 音轨 ＋ 画面：

```bash
python3 scripts/extract_input.py audio <视频> --out inputs/audio.mp3
python3 scripts/extract_input.py frames <视频> --out-dir inputs/frames --max 12
```

`frames` 会生成 `inputs/frames/sheet.jpg` 预览图。能看图的模型看预览图选出可用画面，作为上图素材（常用于 V06 实拍批注）。没有 ffmpeg 时，请用户截几张关键画面并提供文字稿。

## 四、素材用途

每份输入标出一个或多个用途：

| 代号 | 用途 | 喂给哪里 |
|---|---|---|
| S | 选题线索 | 主题 D、读者价值 R |
| F | 事实来源 | 核实、来源条 E09、正文的来源与日期 |
| X | 亲历素材 | 第一人称写法、经验类模板、可信度 |
| A | 上图素材：要放进页面的照片、截图、关键帧 | 风格 V 和版式 L 能否选、每页素材安排 |
| Y | 风格参考 | 风格参数、P1 参考图 |
| C | 角色参考 | 角色资产 |
| K | 约束：页数、平台、必须包含的内容 | 有效配置 |
| M | 修改指令：针对某页、某处 | 修改流程 |

- 用途不明确、又会影响结果时，才问一句。
- 默认判断：用户自己拍的照片 → A＋X；他人笔记或作品截图 → Y（只作参考）；网页文章 → F；一段经历 → X＋S。

每条素材同时标出**可信度**：已确认事实 / 个人经验 / 分析建议 / 待观察 / 演示示例。

## 五、常见组合

| 组合 | 通常走向 |
|---|---|
| 一句话 | 公开资料整理：T14、T06 等；风格以排版型为主 |
| 一句话＋9 张照片 | T16 分享记录、T17 种草；V04 杂志、V05 手账 |
| 一段语音＋几张截图 | 经验分享、教程；V06 实拍批注 |
| 一个表格 | T04 对比、T08 测评；L23 对比表、L30 图表 |
| 一条公众号链接 | 改写已有成稿：压缩成 F2～F4 |
| 一份 PDF 报告 | T03 资讯解读；必须标来源和日期 |
| 风格参考图＋一句话 | 先提取风格参数，再按主题策划 |

## 六、冲突

| 冲突 | 处理 |
|---|---|
| 当次指令和 profile 不同 | 当次优先，只对本次生效；结束时问是否更新默认 |
| 用户的说法和素材不一致（说 5 项，截图里有 6 项） | 指出差异，请用户确认，不悄悄选一个 |
| 素材和公开资料不一致 | 两者都列出，标明来源和日期，由用户决定 |
| 素材撑不起所选风格（选了 V04，只有 1 张照片） | 说明缺口，给两个方案：补素材，或换风格 |

## 七、权利与隐私

- **截图打码**：手机号、真实姓名、订单号、地址、他人头像和昵称，嵌入页面前遮挡：
  `python3 scripts/image_tools.py mask in.png inputs/in.masked.png --rect x,y,w,h --style blur`
  这一项在 `qa-checklist.md` 中检查。
- **他人肖像**：照片里有可识别的他人面孔，提醒用户确认是否获得同意，或模糊处理。
- **未成年人**：不露出儿童正脸、学校、住址等可识别信息。
- **他人内容**：他人的文章、笔记只转述要点并标注来源，不整段搬运；他人的图片不作为上图素材，除非用户确认有权使用。
