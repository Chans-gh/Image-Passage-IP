# 首次初始化与账号配置（profile.md）

## 一、原则

- **全部可选**。不做初始化也能直接开始，一句话就能出一套图。
- **不挡路**。用户直接提了需求，就跳过开场，先做事。
- **边用边存**。每次创作结束问一次「是否把这次的选择存为账号默认」，同意才写回。
- **随时可改**。用户说「更新账号配置」「以后都用 K3」，就改写 `profile.md` 对应项。
- **放在工作区**：`image-passage-work/profile.md`，不放在技能目录里，升级技能不会覆盖。
- **每项标来源**：（填写）（提取）（默认）。提取的值在用户确认前不当作定论。

## 二、开场的四个选择

工作区里没有 `profile.md` 时，先运行 `python3 scripts/workspace.py init`，再给出：

1. **直接开始**：告诉我你想做什么，一句话就行
2. **快速设置**：约 1 分钟，5 个问题
3. **完整设置**：约 5～10 分钟，按 A～H 组逐组填写，每组都可以跳过
4. **从已有内容提取**：发 3～9 篇你过往笔记的截图（图片和正文），我来提取

### 快速设置的 5 个问题（一次问完，不追问）

1. 主要发在哪：小红书 / 微信贴图号 / 两个都发？
2. 一句话介绍你的账号，主要写哪些领域？
3. 主要写给谁看？
4. 喜欢哪种说话方式？（列出 K1～K6 的名字和一句说明）
5. 偏好哪类视觉？有固定的主色吗？（列出 V01～V12 的名字）

### 从已有内容提取

1. 从正文中提取：定位、领域、读者、口吻（K 预设＋称呼、常用表达、emoji 习惯）、常用标签、固定结尾。
2. 从图片中提取（需要模型能看图）：风格 V、主色和辅助色（写颜色名）、字体倾向、版式习惯、署名位置。
3. 把截图复制到 `_assets/style-refs/`，作为以后 P1 的风格参考图。
4. 生成 profile 草稿，所有值标「（提取）」，请用户确认或修改后保存。

纯文本模型看不了截图时，只从用户粘贴的正文中提取，视觉部分请用户用文字描述，或跳过。

## 三、配置项与影响

| 组 | 配置项 | 不填时 | 影响哪里 |
|---|---|---|---|
| A 账号定位 | 平台 | 按当次请求；没说明用小红书预设 | 平台上限 → 篇幅 F 上限、文案 |
| | 一句话定位＋主要领域 D | 每次按主题判断 | 选题建议、R 优先级、T 倾向、H、正文切入角度、账号一致性 |
| | 目标读者 | 按主题推断 | R、H、字数档 S、口吻 K、术语深浅、举例场景 |
| B 创作者 | 身份与可公开资历 | 不提身份 | 第一人称可信度、写法 W、H15 身份背书能否使用、合规（不冒充资质） |
| | 亲历范围 | 不写第一人称亲测 | 核实：哪些能写成「我试过」；没有依据只用「整理 / 分析」口径 |
| | 内容边界、商业合作标注 | 按通用合规规则 | 选题筛选、合规检查、复核 |
| C 口吻 | 口吻预设 K1～K6 | 按模板 T 推荐 | 标题、正文、上图短文案、封面主文案 |
| | 称呼、常用表达、禁用词、emoji | 不用固定称呼和口头禅 | 文案细节；禁用词进入 `check_copy.py --profile` |
| D 视觉 | 偏好风格 V（1～3 个）、不用的风格 | 按内容和路线推荐 | 风格选型。偏好只是优先，内容不适合时说明并换 |
| | 主色、辅助色（颜色名） | 按风格推荐 | 风格参数「色彩」、HEX 推导、P1 |
| | 字体倾向 | 按风格推荐 | 风格参数「字体」；S / H 页使用的字体 |
| | 风格参考图 | 无 | P1 参考图；提取风格参数。他人作品只提取参数，不复制构图和内容 |
| E 品牌 | 署名 / 水印 | 不加 | 每页预留位置；风格参数「组件」 |
| | 固定结尾 | 按体裁收束 | 末页、正文结尾 |
| | 固定标签 | 每次按内容生成 | 标签 = 固定标签＋内容标签 |
| F 人物 | 人物模式、角色资产 | 不使用账号角色 | 每页人物安排、提示词和参考图、svg 嵌入角色 PNG、V08 是否可选 |
| G 工作习惯 | 默认篇幅 F | 按内容判断 | 页数 |
| | 确认节点 | 每次都确认 | 策划、P1 后是否停下等待 |
| | 双图页码 | 不显示 | 页码组件 |
| | 展示提示词 | 否 | 是否在对话里附上每页提示词 |
| | 每页最多重试 | 2 | 失败几次后记为待处理 |
| H 素材库 | 常用素材目录 | 每次单独提供 | 素材是否够用 → V04、V05、V06、V09 能否选 |

技术配置（渲染模式、图片 API、语音转写）写在 `.env`，不写进 profile。见 `render-routing.md`。

## 四、读取与写回

- 每个项目开始时读一次 profile，按 `workflow.md` 第二节的优先级合并。
- 写回时只改用户同意的项，其他项原样保留；修改的项改为「（填写）」。
- profile 中的值和当次请求冲突时，当次优先，只对本次生效。
