# 工作流程：配置、授权、阶段与交付

本文件定义：有效配置怎么取值、项目默认、确认与授权、各阶段步骤、策划格式、变更边界和交付报告。
变量定义见 `content-templates.md`、`visual-system.md`、`copywriting.md`；出图见 `page-generation.md`。

---

## 一、规则归属：每项只有一个定义来源

| 文件 | 定义 |
|---|---|
| `SKILL.md` | 不可覆盖原则、阶段总览、文件索引 |
| `workflow.md`（本文件） | 有效配置、项目默认、确认与授权、阶段步骤、策划格式、交付 |
| `onboarding.md` | 首次初始化、profile.md 各项的影响 |
| `inputs.md` | 输入形式、归一化、素材用途与可信度、权利与隐私 |
| `content-templates.md` | 主题 D、读者价值 R、互动目的 I、篇幅 F、模板 T01～T23、钩子 H、页面角色 |
| `visual-system.md` | 风格 V01～V12、版式 L01～L36、表达元素 E、封面形态 C、风格参数、量化约束、配色、素材保真 |
| `copywriting.md` | 标题、正文、字数档 S、写法 W、口吻 K、标签、来源、互动、合规 |
| `page-generation.md` | 一页一图、规格单、构成方式 G/H/S、页码、逐页流程、失败与修改 |
| `render-routing.md` | 能力判断、渲染路线、风格与版式的路线适配 |
| `prompt-recipes.md` | 生图提示词结构与写法 |
| `html-recipes.md` | HTML/SVG 排版与渲染 |
| `characters.md` | 人物模式、角色资产、角色提示词模板 |
| `qa-checklist.md` | 验收上述规则，不新增标准 |
| `platforms/*.md` | 平台上限（外部硬约束） |

规则冲突时按上表的定义来源处理，不按文件顺序。摘要和定义不一致时以定义为准。

## 二、有效配置

每个字段**分别**按以下顺序取值：

> 当次明确要求 ＞ 本次已经确认的配置（state.json）＞ 账号长期配置（profile.md）＞ 项目默认（本文件及各定义文件）

- 未提及的字段沿用已确认值，不能被一次新提问全部重置。
- 模型的推断只填补空缺，并在策划里用一句话说明。
- 一次任务的改动不自动改变 profile；用户说「以后都用……」或在结束时同意「存为默认」，才写回 profile.md。
- 平台上限（`platforms/*.md`）不属于可覆盖配置：用户要求超过上限时，说明无法发布并给出拆分方案。

### 项目默认

只在没有更高优先级取值时使用。质检核对的是有效配置，不把默认当作硬限制。

| 字段 | 项目默认 |
|---|---|
| 平台 | 小红书预设 |
| 画幅 | 3:4，1242×1656 |
| 篇幅 / 页数 | 按独立信息量选 F（见 `content-templates.md` 第四节）。完整套图常规为 F3～F4（3～10 页），不凑页，也不硬压 |
| 排版底 | 浅色主要阅读区；照片保留必要的自然色 |
| 风格与配色 | 一套一个主风格 V、一个主色体系；没有固定的 V 默认 |
| 页面最低结构 | 页面级主标题、一个核心观点、必要短文案、一个主版式、清晰的信息焦点（F1 单图：封面即全部内容） |
| 页码 | 封面和 F1 不显示；内页底部居中 X / N；F2 可选，默认不显示 |
| 人物 | 未设置时不使用账号角色；剧情人物按内容需要 |
| 标题、正文、标签 | 见 `copywriting.md` |
| 确认节点 | 完整套图确认策划、确认 P1 两个节点；F1 只确认策划 |
| 每页最多重试 | 2 次，之后记为待处理 |
| 提示词展示 | 不在对话里展示，文件始终保存 |

单页、局部修改、只要策划、只要文案的任务不套用完整套图的页数和流程。用户已明确选择其他页数、画幅、字数或人物配置时照做，不再为偏离默认索取许可。

## 三、确认与授权

先策划，后出图。已经完成的节点不重复执行。

| 当前状态或要求 | 下一步 |
|---|---|
| 新建完整套图，还没有已确认的策划 | 提交完整策划，等待确认 |
| 策划已确认，P1 还没确认 | 生成或修改 P1，等待风格确认 |
| P1 已确认，并要求继续 | 连续完成授权范围内的页面，不逐页询问 |
| F1 单图，策划已确认 | 直接出图，不另设 P1 确认 |
| 用户明确说跳过某个确认节点 | 只跳过说到的那个节点；内容核实和逐页质检照常 |
| 用户说「不用确认，直接做完整套」 | 记录授权，完成策划 → 生成并采用 P1 → 继续。记为「免确认授权采用」，不能说成用户看图确认过 |
| 只改现有某一页或文案 | 沿用有效策划和风格，只处理改动及受影响的部分 |
| 要一张独立图片，信息已齐 | 做完该页的必要策划后按单页执行，不扩写成整套 |
| 只要策划，或只要文案 | 完成对应文本，不等待图片阶段 |

- 对刚交付的策划说「按这个出封面」，视为确认这一版策划；对刚交付的 P1 说「继续后面的」，视为确认这一版 P1 并授权继续。
- 确认只绑定具体版本。询问状态、要求继续修改，都不算通过。
- 「全部生成」不等于跳过还没完成的确认节点，要结合当前状态判断。
- 「继续」沿用最近的范围和授权，不自动扩展到新任务。
- 只有尚未取舍、且会改变核心结论、真实素材依据或主风格的事项，才补问。

所有确认、授权都写进 `state.json`（`plan`、`anchors`、`authorization`），继续时从这里恢复，不让用户重复确认。

## 四、阶段步骤

```
⓪ 启动 → ① 输入归一化 → ② 有效配置 → ③ 出图能力 → ④ 范围判断
→ ⑤ 内容价值与核实 → ⑥ 选型与完整策划【确认 1】→ ⑦ P1【确认 2】→ 风格锁
→ ⑧ 逐页生成 → ⑨ 发布文案 → ⑩ 复核与交付报告 → ⑪ 存为默认（询问）
```

### ⓪ 启动

1. 查工作区：`python3 scripts/workspace.py list`。有进行中的项目且用户说「继续」，读 `state.json` 从未完成的节点接着做。
2. 没有 `profile.md`：按 `onboarding.md` 给出四个选择。用户直接提了需求就跳过开场。
3. 新项目：`python3 scripts/workspace.py new <项目名> --platform <平台>`。项目名用简短中文或英文，不含路径符号。

### ① 输入归一化

按 `inputs.md`：每份输入复制到 `inputs/`（链接记录抓取日期），在 `inputs.md` 标出用途和可信度，列出缺口和冲突。后续阶段只读 `inputs.md` 和 `inputs/`。

### ② 有效配置

按第二节逐字段取值。推断的值在策划里标「（推断）」。

### ③ 出图能力

按 `render-routing.md` 判断能不能生图、能不能看图，运行 `scripts/env_check.py`，把结果写进 `state.json` 的 `render`。渲染模式在 P1 采用时锁定。只要策划或只要文案时可以跳过。

### ④ 范围判断

按第三节的表格判断从哪个节点开始、是否需要等待确认。

### ⑤ 内容价值与核实

- 明确**一个具体场景、一个主要问题、一个整篇核心观点**。
- 选读者价值 R 和互动目的 I（`content-templates.md`）。清单要给筛选理由，故事要有具体过程，观点要有场景和理由。
- 需要核实的信息先核实：当前的产品、功能、价格、人物、政策、事件、市场、数据和专业事实。关键结论优先原始来源。记录来源、日期和条件。
- 按需区分：已确认事实、个人经验、分析建议、待观察、演示示例。不要求每页都贴状态标签，在影响判断的位置标出来。
- 公开资料主动核实；第一人称经历和亲测不能编造。缺素材时说明缺口，先推进其他部分。
- 判断横切属性：敏感等级、时效、地域、商业属性（`content-templates.md` 第一节）。

### ⑥ 选型与完整策划

1. 按读者的主要收获选一个主模板 T，必要时借用一个辅助模板并说明主次。
2. 按信息量选篇幅 F 和页数。模板的叙事环节不等于页数。
3. 选钩子 H（封面和标题共用或互补）。
4. 按内容、账号偏好、素材条件**和当前渲染路线的适配度**选一个主风格 V，用一句话说明理由。路线会让风格降级时，在策划里明说。
5. 选封面形态 C；为每页安排一个主版式 L 和主要表达元素 E；为每页定构成方式 G / H / S（`page-generation.md`）。
6. P1 说明阅读价值；内页按体裁推进；末页给适合该体裁的收束。页序角色不固定。
7. 写进 `plan.md`（格式见第五节），版本号从 v1 开始。

完整套图在这里停下，等待确认（除非已获授权）。只要策划的任务到此交付。

### ⑦ P1 与风格锁

1. 按 `page-generation.md` 生成 P1 封面并质检。
2. 用户确认（或按授权采用）后，填写 `style-lock.md`：13 项参数、描述版、精确版。svg / H 页用 `scripts/palette.py tokens` 生成 `render/tokens.css`。
3. 首张内页完成后，把正文、卡片、表格、图片处理的样式补进风格锁，作为**内页锚点**。不新增确认节点。
4. `state.json`：`anchors.P1`、`render.locked = true`。

复用已有风格或只改单页时，不重建 P1。

### ⑧ 逐页生成

按 `page-generation.md` 第六节的流水线，每页：规格单 → 编译 → 生成 → 质检 → 修正 → 采用（`workspace.py adopt`）。用户已授权继续时连续完成，不逐页询问。被中断后依据 `state.json` 继续，不重复、不漏页。

### ⑨ 发布文案

按 `copywriting.md` 写进 `copy.md`，运行 `scripts/check_copy.py`。图片未完成前写的文案标为「文案版本」，不声称已与图片逐页核对；图片完成或改动后再同步。

### ⑩ 复核与交付

1. 按 `qa-checklist.md` 第 I 节复核。
2. 运行 `python3 scripts/workspace.py status <项目>`，确认页数、顺序、采用版本、final/ 文件和文案一致。
3. 按第七节的格式报告。

### ⑪ 存为默认

询问一次：「是否把这次的选择（口吻、风格、主色……）存为账号默认？」用户同意才写回 `profile.md`，并标来源为「填写」。用户拒绝或没回答就不写。

## 五、完整策划的格式

写进 `plan.md`（模板 `templates/plan.md`）。

**整篇说明**：主题、读者、场景与问题、核心观点、R、I、F 与页数（理由）、主模板 T（辅助模板与理由）、钩子 H、主风格 V（理由与路线适配）、封面形态 C、主色（颜色名）、人物模式、渲染路线与各页构成方式、口吻 K / 写法 W / 字数档 S、平台、与默认不同的关键配置；来源与素材缺口；横切属性。

**每页**：

1. 正式页码与页面角色
2. 页面标题、核心观点
3. 准备实际上图的文字（逐字）
4. 主版式 L、表达元素 E、构成方式、主要素材、区域与阅读顺序
5. 信息焦点及强调方式
6. 来源、示例标记、账号角色或剧情人物安排

焦点可以是句子、数字、动作、结果或转折。已经表达清楚时，不再加重复的结论卡。策划中的「待补素材」不能作为最终页面里的占位内容。

在对话里交付策划时，给一个精简版（整篇说明＋每页一行），完整版在 `plan.md`。

## 六、变更边界

策划确认前可以推荐替代方案。确认后，下列改动**不能悄悄进行**，必须说明并重新确认：

- 把实测改成资料整理，把实拍改成模拟图
- 改变核心结论
- 改变主风格；更换渲染模式（视为改变主风格，需重新确认 P1）
- 增删页、调整顺序（同时更新策划编号、总页数、所有受影响页的页码、文案）

改动后在 `plan.md` 的变更记录里写一行，版本号加一。

## 七、交付报告

只把实际通过检查的结果标为完成。格式：

```markdown
**完成**：P01–P06（image-passage-work/<项目>/final/）
**待处理**：P07｜缺少「换盆后」的照片 → 补拍后可继续，或改为文字版式
**质检**：P01–P05 看图检查通过；P06 只做了脚本检查，未经视觉检查，请抽查
**文案**：copy.md（标题 16 字，正文 412 字，标签 5 个；check_copy 无错误）
**待核实**：小红书正文上限未核实，发布前以 App 为准
```

不把待修的图片混入最终版本；受阻的页不标为完成，已授权且不依赖它的部分继续完成。

## 八、不可覆盖的原则

以下不属于美术配置，任何授权和配置都不能覆盖：

- 不虚构来源、亲测、经历、数据、官方结论、评论和用户反馈。
- 明确标注的虚构和示例可以用，但不能改称为真实证据。
- 不把未完成说成已完成；免确认授权不能说成用户确认过。
- 真实素材的关键内容保真（`visual-system.md` 第八节）。
- 一页一图：不用多页拼版冒充正式页面（`page-generation.md`）。
