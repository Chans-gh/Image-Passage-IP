# 出图：页面单位、构成方式、流水线

本文件约束正式图片怎么生成。路线判断见 `render-routing.md`；提示词写法见 `prompt-recipes.md`；HTML 写法见 `html-recipes.md`；质检见 `qa-checklist.md`。

下文 `<项目>` 指 `image-passage-work/<项目名>`，脚本路径相对技能目录。

## 一、一页一图

- 「批量出图」「继续剩余页面」「生成全部内页」都指**按顺序连续生成多张独立单页**。批量改变要完成的页数，不改变页面单位。
- 每张正式图片只对应当前一页、一个核心观点，使用有效画幅，本身可以作为正式单页使用。
- 页面不依赖从其他合集里裁切才能成立。

**允许的单页内部结构**（同一页、同一个核心观点下）：多个清单卡片、分类标签；左右对照、前后对比；一个情境的漫画分格或短对话；照片与细节图组合、手账拼贴；多个图表面板共同支持一个结论；表格、矩阵、工作纸、路线图。这些是信息分区，不是多页。

**禁止作为正式页面**：把多个完整页面缩小并排在一张图里；一张图里出现属于不同正式页面的页码，或多个独立的海报版式；用九宫格、storyboard、contact sheet、海报墙冒充单页；先生成合集再裁切其中一格；要求正式出图却只交付整套预览。

正式页码指本套图的页面导航；步骤编号、对象编号、时间、数据、书页原页码、截图里的进度都不是正式页码。截图、书页和卡片里自带的标题不构成另一张完整页面。

## 二、构成方式：G / H / S

中文文字是生图模型的主要短板：字少时大多能写对，字多容易错字、乱码、漏字；真实截图交给生图模型重画，数字和文字可能被改掉。所以每一页单独决定画面和文字由谁做。

| 构成方式 | 画面 | 文字 | 适合 |
|---|---|---|---|
| **G 整图生成** | 生图模型 | 生图模型 | 字少、以画面为主的页：封面、插画页、漫画页、大字报 |
| **H 底图＋叠加** | 生图模型画底图，按版式留出空白区 | HTML 叠加准确的文字；真实截图和照片原样嵌入 | 字多的内页、表格、步骤、带截图的页 |
| **S 纯排版** | HTML / CSS / 内联 SVG | HTML | svg 路线的全部页面；排版型风格（V03、V10、V11、V12）；需要精确数据的页 |

### 自动选择规则

按顺序判断，命中即停：

1. 渲染模式是 svg → **S**。
2. 页面里有需要保真的截图、照片或精确数据 → **H**（素材原样嵌入，模型只画周围的底图）。H 不可用时 → **S**。
3. 上图文字超过阈值 → **H**。默认阈值：正文超过 30 字，或超过 4 条要点，或有表格（L17、L18、L23、L30 默认属于此类）。
4. 其余 → **G**。

- 同一套里 G 和 H 可以混用，但字体必须统一：G 页的字体描述要贴近 H 页实际用的字体；也可以把 G 页的标题改为叠加。
- H 需要环境能运行 `render_page.py`（Playwright＋Chromium）并下载了中文字体。`env_check.py` 的 `compose_H_available` 会给出结论。
- 阈值是初始默认，各生图模型的实际上限需要实测；某个模型在某套图里反复写错字时，可以下调阈值，并记进 `state.json` 的 `log`。
- 用户指定了构成方式时照做。构成方式写进规格单和 `state.json` 的 `pages.PNN.composition`。

## 三、页码与编号

- 显示规则见 `visual-system.md` 第五节（方案 B：封面和 F1 不显示，内页底部居中 X / N）。
- 修改或单独交付现有 P5 时沿用全套编号（5 / 9），不重编号为 1 / 1。
- 新建一张独立作品且配置显示页码时，编号为 1 / 1。
- 增删页或换序后，先更新 `plan.md` 的编号和总页数，再同步所有受影响的正式页、文案和采用版本。不能让新旧分母混用。S / H 页改页码只需改 HTML 后重新渲染。
- 已采用 P1 里的旧页码只作为参考图内容，不覆盖当前页的有效编号。

## 四、页面规格单

每页先写 `pages/PNN/spec.md`（模板 `templates/spec.md`），只含本页信息，与路线无关。生图工具和渲染脚本**只看**规格单、风格锁和参考图。

```bash
python3 scripts/workspace.py page <项目名> P03 --composition H
```

| 字段 | 内容 |
|---|---|
| 页码 | 3 / 8；是否显示 |
| 页面角色 | 封面 / 问题 / 步骤 / 对比 / 收束…… |
| 构成方式 | G / H / S |
| 版式 | L 编号；区域划分、比例、阅读顺序 |
| 上图文字 | 逐字列出，每条标层级：主标题 / 副标题 / 正文 / 注释 / 数字。写成「」包起来，`ocr_check.py --expect-file` 会读取 |
| 焦点 | 强调什么、怎么强调（≤3 处） |
| 素材 | 引用 `inputs.md` 编号；放在哪个区域；保真（原样嵌入）还是风格化 |
| 人物 | 不出现 / 角色名＋动作＋位置＋大小 |
| 表达元素 | E 编号 |
| 来源条 | 有 / 无；内容 |
| 禁止项 | 本页特有的禁止项 |
| 参考图 | 本页要带的参考图及作用 |

## 五、信息隔离与参考图

每次生成只能用：已采用的 P1、风格锁、适用的角色参考、**当前页**的规格单和素材。其他页的完整标题、正文、页码和版面不能作为画面输入；相邻页只用来理解逻辑，不在画面里展开。

| 参考图 | 何时带 | 作用 |
|---|---|---|
| P1 封面（`final/P01.png`） | P2 起每页 | 风格锚点 |
| 首张内页 | P3 起每页 | 内页锚点：正文、卡片、表格的样式 |
| 角色设定图 / 动作图 | 本页有角色时 | 角色一致性 |
| 本页素材 | 本页引用了素材时 | 照片、截图 |

- S 页不需要参考图，风格由 `render/tokens.css` 保证。
- 生图工具不支持参考图时，只能依靠风格锁描述版保持一致，一致性会明显变弱。这时多用 H 页（文字层由代码保证一致），并在策划阶段告诉用户。
- 同一套里锁定生图参数：工具、模型、尺寸、质量档、seed（支持时），写进 `state.json` 的 `render`。

## 六、单页流水线

```
spec.md → 编译 → 生成 vN.png → 质检 → 通过：adopt → final/PNN.png
                               └ 不通过：修正 → vN+1 → 质检
                                 超过重试上限（默认 2）：block，继续其他页，最后报告
```

### 1. 读取与确认

读 `plan.md`、`style-lock.md`、`state.json`；确认下一张未完成的页码、授权范围（免确认的任务不重复索取审批）。

### 2. 写规格单

从 `plan.md` 提取当前页的实际文案、版式、素材和人物安排，写进 `spec.md`。检查：独立页面单位、有效画幅、主标题、核心观点、正式编号。

### 3. 按构成方式编译与生成

**G（native）**

1. 按 `prompt-recipes.md` 把规格单编译成 `pages/PNN/prompt.md`。
2. 把代码块里的提示词和参考图交给环境里的生图工具。
3. 把结果保存为 `pages/PNN/vN.png`。尺寸不是 3:4 时：`python3 scripts/image_tools.py fit 原图.png pages/PNN/vN.png`

**G（api）**

```bash
python3 scripts/call_image_api.py --prompt-file <项目>/pages/P01/prompt.md \
  --ref <项目>/final/P01.png --out <项目>/pages/P02/v1.png
```

脚本读取 `.env`，保存原图 `v1.raw.png`，并裁切适配为 1242×1656。先用 `--dry-run` 查看将要发送的请求（不含 KEY）。

**H（底图＋叠加）**

1. 写底图提示词（`prompt-recipes.md` 第五节：指定留白区，**不画任何文字**），生成 `pages/PNN/base.png`。
2. 编辑 `pages/PNN/page.html`（由 `workspace.py page --composition H` 从 `templates/page-compose.html` 创建），把底图设为 `.base-layer`，文字和保真素材放进 `.zone`。
3. 渲染：`python3 scripts/render_page.py <项目>/pages/P03/page.html --out <项目>/pages/P03/v1.png`

**S（纯排版）**

1. 编辑 `pages/PNN/page.html`（由 `templates/page.html` 创建），按 `html-recipes.md` 使用 `base.css` 的版式类和 `render/tokens.css`。
2. 渲染：同上。脚本会同时检查溢出、出界、安全边距、字号、字体、图片加载、重叠和高亮数量，有错误时退出码为 1。

### 4. 质检

按 `qa-checklist.md` 第 G、H 节和 `state.json` 的 `render.qa_mode`：

| qa_mode | 做法 |
|---|---|
| visual | 模型看 `vN.png`，逐项检查结构、文字、数字、素材、人物、风格、页码 |
| script+ocr | S / H 页看 `render_page.py` 的报告；G 页 `python3 scripts/ocr_check.py vN.png --expect-file spec.md` |
| script-only | S / H 页看脚本报告；G 页无法检查文字，记为「未经视觉检查」 |

结果写进 `pages/PNN/qa.md`（每个版本一段：版本、检查方式、问题、结论）。

### 5. 修正、采用或阻塞

```bash
python3 scripts/workspace.py adopt <项目名> P03 v2 --qa pass               # 看图检查通过
python3 scripts/workspace.py adopt <项目名> P03 v1 --qa pass-script-only   # 只有脚本检查
python3 scripts/workspace.py adopt <项目名> P03 v1 --qa unchecked          # 无法检查，报告里注明
python3 scripts/workspace.py block <项目名> P05 "缺少换盆后的照片"
```

`adopt` 把版本复制到 `final/P03.png` 并更新 `state.json`。能在现有条件下修正的问题先修正；缺素材等确实受阻的页记为待处理，不标完成。

### 6. 继续

默认按页码继续。某页受阻时，可以推进不依赖它且已授权的其他页；P1 或共同依据未满足时，不越过依赖它的阶段。用户已授权继续剩余页时，不逐页询问。被中断后依据 `state.json` 继续。

## 七、失败判定

满足任意一项即判定为正式单页生成失败：

- 出现属于不同正式页面的页码，或本页编号与策划不一致。
- 存在两个或以上完整页面版式；多张独立海报缩小后塞进一张画布。
- 需要从合集裁切才能得到当前页；交付的是整套预览。
- 上图文字与规格单不一致（错字、漏字、多字、乱码）。
- 保真素材的关键内容被改变。

单页内部的卡片、漫画分格或对象编号本身不构成失败，但要检查它们是否服务一个核心观点。

## 八、修改与错误处理

| 构成方式 | 改文字 | 改画面 |
|---|---|---|
| G | 工具支持局部编辑就编辑（`prompt-recipes.md` 第六节）；否则改提示词重新生成 | 同左 |
| H | 只改 `page.html` 重新渲染，几秒完成，不动底图 | 重新生成底图，文字层不变 |
| S | 改 `page.html` 重新渲染 | 同左 |

- 每次修改都生成新版本号（v2、v3），旧版本保留，不覆盖。
- 多页拼版：放弃该结果，重新提取当前页，生成完整的独立单页。不从错误拼版中裁切、放大或沿用。
- G 页文字反复出错：改为 H，或减少上图文字（移到正文）。
- 真实素材的关键内容按 `visual-system.md` 第八节保真，不能因重绘整页改变证据。
- 裁切单张照片、截图或局部细节以完成排版是允许的。
- 用户说「看一下 P3 的提示词」「把 P3 提示词里的……改成……再出一次」时，展示或修改 `pages/P03/prompt.md` 后重新生成。

未通过的页不能记为已完成，也不能把待修图片混入最终版本。

## 九、预览

只有用户明确要求整套预览、九宫格展示或作品展示图时，才制作多页同屏图：

```bash
python3 scripts/image_tools.py sheet <项目>/preview.jpg <项目>/final/P*.png --cols 3 --label
```

预览不能替代正式独立页面。封面缩略图检查也可以用它看 1/3 尺寸下的效果。

## 十、文件与可见度

```
<项目>/pages/P03/
├── spec.md      页面规格单
├── prompt.md    G / H 页的提示词（H 页是底图提示词）
├── base.png     H 页的底图
├── page.html    H 页的文字层，或 S 页的源文件
├── v1.png v2.png
└── qa.md        每个版本的质检结果
```

- 默认在对话里只展示图片和简短说明，不展示提示词和 HTML。
- profile 里「展示提示词：是」时，每页生成后附上提示词。
- 文件始终保存，方便复现、排查和修改。
