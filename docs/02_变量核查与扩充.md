## 〇、先定一个总原则：变量之间的关系

V3.1 里有些变量混在一起用（例如「内容价值路径」和「模板」、「封面切入」和「标题方向」）。重构后按下面的顺序决策，每个变量只回答一个问题：

```
主题领域 D        讲什么
   │
读者价值 R  ──┐   读者为什么看（主 1 个）
互动目的 I  ──┤   希望读者做什么（主 1 个）
   │          │
篇幅形态 F  ──┤   用几张图讲（1 张 / 2 张 / 短套 / 标准套 / 长套）
   │          │
内容模板 T  ◀─┘   怎么讲（叙事结构）
   │
钩子 H            用什么吸引点击（封面和标题共用同一套）
   │
视觉风格 V        整套长什么样
   │
封面形态 C        封面怎么摆（引用版式 L，追加封面规则）
单页版式 L        每页的骨架
表达元素 E        骨架里放什么
   │
文案：标题（用 H）· 正文（写法 W、字数档、口吻 K）· 标签 · 合规标注
```

新增的轴：**R、I、F、H、C、E、W、K**。其中 R 和 I 替代了 V3.1 的「内容价值路径」，H 统一了「封面切入」和「标题方向」。

## 一、主题领域 D（8 类 → 20 类）

### 1.1 核查结论

- V3.1 的 8 类偏向职场和效率，缺少平台上占比很大的美妆、穿搭、美食、健康、育儿、宠物、文娱、家居等类目。
- 没有区分敏感等级。美妆功效、健康、财务、法律、心理这些领域需要更严格的来源和表达边界。
- 「节日节点」「热点」不是主题，而是时效属性，应该单独作为横切属性。
- 「校园」「新手」这类是读者人群，属于「目标读者」，不放进主题。

### 1.3 横切属性 🆕

## 二、内容模板 T（15 → 23）＋ 篇幅形态 F 🆕

### 2.1 核查结论

- V3.1 默认 3～10 页，**没有 1 张和 2 张图的笔记**。但单图大字报、单图投票、单图 plog、两张前后对比都是平台上非常常见的形态。
- 如果为「单图」专门再造一批模板，会和现有模板重复，例如「一图看懂」本质上还是 T14 科普。因此新增一个独立的**篇幅形态 F** 轴：同一个 T 可以用不同篇幅来讲，按规则压缩。
- 平台上有几类常见笔记，现有 15 个模板都覆盖不到：纯分享记录、单品种草、征集提问、投票选择、可保存的物料图、账号通知、趣味吐槽、他人故事。这些新增为 T16～T23。

### 2.2 篇幅形态 F 🆕

| 编号 | 形态 | 张数 | 典型结构 | 流程差异 |
|---|---|---|---|---|
| F1 | 单图 | 1 | 封面即全部内容 | 策划确认后直接出图；不另设 P1 风格确认节点；默认不显示页码（待定，见 4.3） |
| F2 | 双图 | 2 | 封面＋交付页 / 问题＋答案 / 前＋后 / A＋B / 主体＋细节 / 同一物料的两个版本 | P1 确认后出 P2 |
| F3 | 短套 | 3～5 | 封面＋2～4 张内页 | 同 V3.1 |
| F4 | 标准套 | 6～10 | 同 V3.1 | 同 V3.1 |
| F5 | 长套 | 11 张以上 | 建议加目录页 L34 | 同 V3.1；上限以平台为准 ❓ |

**压缩规则**（适用于所有 T）：

- 模板的叙事环节不等于页数。F1、F2 时，只保留「核心观点＋最关键的支撑」，其余环节移到正文。
- 模板「必须」项中，影响判断的条件（来源、测试条件、适用人群）不能因为压缩而丢失。放不进图片时写进正文，并在图上留一句简短提示。
- 默认篇幅由内容信息量决定，不凑页，也不硬压。用户指定张数时按指定执行。

### 2.4 新增模板定义

#### T16｜分享／记录 🆕

适合：plog、OOTD、日常记录、晒图、旅行片段、作品展示。
结构：一个瞬间或主题 → 画面 → 细节 → 一句感受 → 可选的实用信息（地点、单品、参数）。
必须：画面使用用户提供的真实照片；生成的图只能作为版式装饰或明确标注为插画。
避免：AI 生成图冒充实拍；硬加「干货」变成别的模板。

#### T17｜单品推荐／种草 🆕

适合：一个物品、一款工具、一家店、一本书。
结构：适合谁、什么场景 → 推荐理由（1～3 条）→ 怎么用 → 不适合谁或有什么限制 → 价格和渠道信息（注明日期）。
必须：说明推荐依据（亲测需要用户提供依据）；有商业合作时必须标注；写出限制。
避免：只有优点；绝对化用语（见第八节）；功效承诺。

#### T18｜征集／提问／求助 🆕

适合：求推荐、求建议、征集经验、征集作品、请大家补充。
结构：我的处境和条件 → 一个具体的问题 → 已经尝试或考虑的选项 → 希望得到什么样的回答。
必须：问题具体、可回答；交代足够的条件，让人能给出有用的建议。
避免：捏造评论或「评论区精选」；问题空泛到无法回答。

#### T19｜投票／选择题 🆕

适合：二选一、多选一、站队讨论、你会怎么做。
结构：情境 → 选项 A/B（最多 4 个）→ 每个选项的代价或特点 → 邀请选择（作者倾向可选）。
必须：选项可比、条件对等；话题可以讨论但不引战。
避免：性别、地域、群体对立；用投票包装已有结论。

#### T20｜可用物料／模板图 🆕

适合：手机壁纸、打卡表、计划表、速查卡、手账模板、清单模板。
结构：物料本体（图）→ 使用说明（正文）→ 适配说明（尺寸、打印、使用场景）。
必须：素材和字体有使用授权；物料本身可直接使用，不是宣传图。
避免：用「评论区扣 1 领取」之类的方式换取互动（见第八节）。

#### T21｜通知／预告／招募 🆕

适合：账号公告、连载预告、更新说明、活动招募、直播预告。
结构：一句话说明是什么 → 时间、地点、方式、规则 → 参与方式或注意事项。
必须：时间、规则、条件准确完整；涉及抽奖或福利时遵守平台规则。
避免：诱导关注、点赞、转发；夸大福利。

#### T22｜趣味／吐槽 🆕

适合：职场梗、生活小尴尬、反差对比、自嘲。
结构：熟悉的情境 → 反差或夸张 → 落点（笑点或一句共鸣）。
必须：素材自有或可合法使用；明确是夸张表达。
避免：攻击特定群体或个人；直接使用影视截图、表情包等有版权的素材。

#### T23｜访谈／他人故事 🆕

适合：人物访谈、朋友的经历、读者投稿、行业从业者分享。
结构：人物与背景 → 关键经历 → 做法或观点 → 作者的观察 → 可借鉴条件。
必须：内容来自真实的访谈或投稿，并取得当事人同意；隐去不必要的个人信息；作者观点和当事人原话分开。
避免：虚构人物冒充真实访谈；把当事人的个案写成普遍规律。

## 三、单页版式 L（14 → 36）

### 3.1 核查结论

- 现有 14 种覆盖了结构图示类，但平台上常见的几类缺失：**纯字排大字报**、金句卡、干货段落页、问答卡、对错示范（❌/✅）、多列对比表、排行榜、卡片网格、单品卖点标注、多图拼贴、截图步骤、角色讲解、投票卡、目录页、尾页。
- 版式只定义骨架。骨架里放什么由表达元素 E 定义（第六节），封面的额外规则由封面形态 C 定义（第七节）。

### 3.2 版式总表（按类）

文字量上限是建议默认值，按 1242×1656 画布、手机阅读估计，可被有效配置覆盖。

**A. 字排类**

| 编号 | 版式 | 适合的页面 | 主元素 | 文字量 | 控制 |

## 四、风格参数（Style Anchor）核查

### 4.1 发现的问题

| # | 问题 | 说明 | 建议 |
|---|---|---|---|
| 1 | **只有封面一个锚点** | 封面常用大字报（L15）、大图（L19）等形态，没有正文、表格、卡片。后续内页能继承的信息不足。V3.1 用「首张内页适配检查」补救，但没有把检查结果记为锚点 | 改为**双锚点**：P1 是封面锚点，首张内页是内页锚点。内页锚点**不新增确认节点**，只记录参数 |
| 2 | **页码规则与封面、单图冲突** | V3.1 默认所有页「底部居中 X / N」。大字报封面和 F1 单图显示「1 / 1」会破坏画面 | 待你决定（见 4.3） |
| 3 | **参数无法区分「可精确控制」和「只能描述」** | native 模式无法保证精确色值和字体；svg / api 可以。V3.1 只写「记录参数」 | 每个参数分两栏：颜色名、字体感等描述值（所有模式），HEX、字体名、px 等精确值（svg 必填，api 尽量填） |
| 4 | **缺少版心与网格** | 只有「密度」里提到安全边距。页面之间的对齐方式、标题位置不一致，是套图看起来「不像一套」的主要原因 | 新增「版心与网格」参数 |
| 5 | **缺少渲染模式** | 同一套图中途换渲染模式，风格会断层 | 新增「渲染模式」参数，并锁定 |
| 6 | **缺少文字规范** | 中英混排、数字格式、标点、图上是否放 emoji 都没有规定 | 新增「文字规范」参数 |
| 7 | **组件样式分散** | 页码、来源条（Evidence Strip）、标签徽章散在不同文件里 | 合并为「组件」参数 |
| 8 | **「人物」参数和角色资产没有关联** | 只写是否启用 | 改为「角色」：记录资产路径、出现规则、剧情人物外观卡 |
| 9 | **缺少量化约束** | 「手机可读」「不密集」没有数值，质检难以判定 | 给出建议默认值（见 4.4） |

### 4.5 颜色名 → HEX 的规则（按你的决定）

- 策划和风格参数里**只写颜色名**，例如「鼠尾草绿 + 暖米白 + 炭灰」。
- 渲染时：
  - **native**：把颜色名和 P1 参考图一起写进提示词。
  - **svg / api**：在 P1 渲染时，由颜色名推导一组 HEX 并**写进 state.json**。之后每页都用同一组 HEX，不允许每页重新推导。
- 计划在 `visual-system.md` 里提供一张「常用颜色名 → HEX 参考表」，保证同一个颜色名在不同项目里大致一致。

## 五、内容价值：拆成读者价值 R＋互动目的 I ✏️

### 5.1 核查结论（重点审查）

V3.1 的「内容价值路径」（操作、理解、选择、资源、变化判断、共鸣、经验、记录，共 8 项）有四个问题：

1. **只覆盖了实用价值和少量情感价值。** 缺少娱乐、治愈、审美灵感、激励、社交谈资、身份认同、参与表达，而这些是平台上大量笔记的主要价值。
2. **把「读者得到什么」和「作者希望读者做什么」混在一起。** 「记录」是作者的动作，不是读者的收获。
3. **完全没有互动目的。** 征集、投票、提问、晒图、追更这类笔记无从定义。
4. **定义了却没有被使用。** 这 8 项只在 00 第三节出现，不影响模板、钩子、写法和收尾的选择。

重构后：**R 回答「读者为什么看」，I 回答「希望读者做什么」**。两者共同决定 T、H、写法 W 和收尾方式。

## 七、封面：钩子 H＋封面形态 C ✏️

- V3.1 的「封面切入」只有 4 项（结果、问题、场景、核心主张），而且和 03 的「标题方向」是两套平行的列表，没有关联。

## 八、文案规则重构 ✏️

### 8.1 重构原则（沿用专家整体设计）

1. **一个规则只在一处定义**：文案的数值和写法定义在 `copywriting.md`；平台上限定义在 `platforms/*.md`；钩子 H 定义在内容模板文件中，封面和标题都引用它。
2. **分清两类约束**：
   - **平台上限**是外部硬约束，不属于可覆盖配置。用户要求超过上限时，说明无法发布并给出拆分方案。
   - **项目默认**在平台上限之内，按「当次 ＞ 本次已确认 ＞ 账号长期 ＞ 项目默认」继承，可以被覆盖。
3. **由变量驱动，不单独定规则**：写法由 T 决定；图文分工由 F 决定；收尾和互动由 R、I 决定；标题用 H；语气用 K。
4. **真实性不可覆盖**：第一人称、亲测、背书、数据必须有依据（延续 V3.1）。

### 8.2 文案的组成 ✏️

| 组成 | 位置 | 定义 |
|---|---|---|
| 封面主文案 🆕 | 图上 | 见 7.4 |
| 发布标题 | 发布栏 | 见 8.3 |
| 正文 | 发布栏 | 见 8.4～8.6 |
| 话题标签 🆕 | 正文末尾 | 见 8.8 |
| 来源与日期 | 正文或图上来源条 | 延续 V3.1 03 第六节 |
| 互动句 | 正文末尾 | 由 I 决定，见 5.3 |
| 合规标注 🆕 | 正文开头或末尾 | 商业合作、敏感领域提示，见 8.9 |

### 8.3 发布标题（用钩子 H）

- **长度**：项目默认 ≤20 字。平台上限：小红书和微信贴图号都待核实 ❓。
- 写清具体问题、收获、场景或判断，让读者一眼知道和自己有没有关系。
- 和封面用同一个钩子或互补钩子，不逐字照抄封面。
- 钩子的强度与证据强度匹配：H10、H14 要有来源；H11、H15 要有真实依据。
- 不夸大效果，不把个案写成普遍结果，不制造焦虑或群体对立。
- 商业内容不用绝对化用语（见 8.9）。

### 8.4 图文分工（由 F 决定）✏️

替代 V3.1 的「体裁分工」表。

| 篇幅 | 图片承担 | 正文承担 |
|---|---|---|
| F1 单图 · 信息型（一图看懂、清单、物料） | 全部核心信息 | 简短说明用法和条件 → 正文**降一档** |
| F1 单图 · 钩子型（大字报、提问、投票） | 一个观点或问题 | 背景、理由、展开 → 正文**升一档** |
| F2 双图 | 钩子＋交付 | 补充条件和细节 |
| F3～F5 套图 | 主体内容 | 补充图片没展开的条件、经验、细节和延伸 |

通用规则（延续 V3.1）：正文不是逐页转写图片，也不能和图片证据矛盾。

| S0 一句话 | ≤50 字 | T16（F1）、T22（F1） |
| S1 短 | 50～150 字 | T16、T19、T20、T21、T22 |

### 8.9 合规 🆕

|---|---|
